# Качество фотографий

`SiteImage` выводит обычный `<img>` без клиентского image runtime. Для основных
фотографий и обложек доступны локальные WebP-копии шириной 320–1600 пикселей,
созданные из лучших подтверждённых исходников с quality=88. Браузер выбирает
размер через `srcset` и `sizes` с учётом плотности экрана. Последний кандидат и
резервный `src` — неизменённый исходник в полном разрешении. На VPS и Cloudflare
это работает одинаково, без зависимости от image endpoint.

`data/photo-sources.json` связывает уменьшенные копии с подтверждёнными исходниками
того же изображения: 15 кадров галереи шириной 2000 пикселей, полные скриншоты
отзывов и оригинальные JPEG с исходного сайта. Происхождение скачанных файлов
и размеры записаны в `public/media/originals/manifest.json`.

Исходные файлы не перерисованы и не пересохранены. Главный снимок остаётся
1767×1255, тарифы «Премиум» и «Стандарт» — 900×600. Часть обложек имеет исходное
разрешение 500×500: большего файла той же композиции не найдено. Изображения без
подготовленных вариантов продолжают загружаться в полном разрешении. Для
дальнейшего улучшения детализации таких фотографий нужны более крупные исходники.

## Подготовка адаптивных файлов

```bash
node scripts/prepare-responsive-images.mjs
```

Скрипт использует уже установленный `sharp`, обрабатывает `media/home` и
`media/covers`, разрешает пути через `photo-sources.json`, не увеличивает исходники
и записывает `data/responsive-photos.json` и `public/media/responsive/`.
Имена включают хеш исходника и настроек кодирования, поэтому кеш обновляется
при замене фотографии. Эти файлы входят в публикацию; запуск конвертера на
production-сервере не нужен. Старые миниатюры из `media/optimized/home` и
`media/optimized/covers` для крупных фотографий не используются.

`HOME_HERO_SIZES` соответствует существующей мобильной сетке первого экрана.
При изменении этой сетки обновляйте `sizes` одновременно у фото и его preload.
Галереи сохраняют исходное разрешение, но добавляют `src` только активному
и соседним кадрам. Место под остальные кадры резервируется по их пропорциям.

Проверка: `npm run lint`, `npm run build`, `node --test tests/*.test.mjs`
и `npm run check:assets`. Подробности мобильной оптимизации — в
[mobile-performance.md](mobile-performance.md).
